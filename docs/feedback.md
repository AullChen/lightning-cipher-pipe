# 反馈调度 v1

`Policy.mode=1` 启用 FEEDBACK；`mode=0` 为 FIXED。两个模式共用认证、持久回执、完整性验证、重试和[计量口径](metrics.md)。`FixedTransferClient` 保留原 API 名称，现支持两种模式。FIXED 不执行反馈决策。

FEEDBACK 只改变后续新块的大小、并发窗口和 ZSTD 等级。控制参数限制在 Open 认证的策略范围内：块大小 256 KiB–8 MiB、窗口 1–16、ZSTD 1–5。NONE 的等级固定为 1。物理并发还受对端槽位和整块生命周期字节预算约束。已准备的未确认块保持原索引、偏移、明文摘要和压缩材料；新一轮重试只重新封装加密。

## 决策规则

每轮至少有 16 个非重试有效 ACK，且经过至少 2 秒；短传输保持初始参数。除收到认证 BUSY 的压力处理外，缺失或无效观测时保持参数。每个传输仅维护最近 64 个样本、当前聚合、一个试探和冷却计数，不持久化调度历史。

1. 收到 BUSY 或完整轮的排队占比大于 0.25，先撤销试探，再将窗口减半至策略下限，进入两轮冷却。BUSY 在重试前生效；缩窗不撤销旧块预算，而是限制重试实际并发。压力发生后的部分轮次重新计量。
2. 没有试探且冷却结束时，按窗口、压缩、块大小轮换考察，一次只调整一个可行维度。窗口占满比例至少 0.8，且未到 EOF、未因预算受限时，试加一个窗口。
3. 压缩忙碌比例至少 0.8 时试降一级；不超过 0.5、窗口占满比例至少 0.8、压缩比不超过 0.9 时试升一级。
4. 刚完成的一轮有重试时试将块大小减半；无重试、窗口占满比例至少 0.8、排队占比不超过 0.1 时试加倍。所有候选值限制在已认证范围内，不可行的维度跳过。

一次试探保持新参数两个完整轮次，以两轮合计首次确认字节除以合计耗时评估。吞吐提高至少 5%、最近有效 ACK 的 P95 不超过基线 1.2 倍、试探期间没有新增 BUSY 或预算失败才保留；否则回退。评估后冷却两轮。压力处理优先于试探评估，回退不会恢复到压力处理前的旧窗口。

## 启动器

在源配置中设置 `scheduling=FEEDBACK`。`chunkBytes` 和 `zstdLevel` 为初始值；`inFlightChunks` 为窗口上限，`initialWindow` 可指定初始窗口，默认等于上限。块大小范围从 256 KiB 到 `min(maxPlainBytes, 8 MiB)`；ZSTD 等级范围为 1–5。最大块仍须满足帧大小和压缩上界检查。FIXED 不接受 `initialWindow`，继续以 `inFlightChunks` 作为固定窗口。

这些阈值是 policyVersion 1 的启发式规则。单轮观测无法区分链路变化与调参因果；当前测试验证行为、资源和内容不变式，尚未证明性能收益。改变阈值需提升策略版本并提供实验依据。
