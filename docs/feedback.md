# 反馈调度

固定策略（Policy.mode=0）和反馈策略（mode=1）共用认证、发送、持久回执、对账和完整性校验路径。`FixedTransferClient` 提供两种模式的入口。

## 参数与协商

Open 认证策略版本、参数范围和初始值。反馈支持 256 KiB–8 MiB 块、1–16 窗口及 ZSTD 1–5；NONE 的等级为 1。目标根据明文上限、槽位和字节预算收紧范围，源端复核接受事实。物理并发取策略窗口、协商槽位和完整块预算容量的共同上限。

反馈改变后续新块的参数。已准备块保留原索引、偏移、摘要与压缩材料，重试时重新进行 HPKE 封装。

## 观测与试探

每轮至少经过 2 秒并取得 16 个有效 ACK。控制器保存最近 64 个样本、当前聚合、一个候选及冷却计数。指标定义见[计量口径](metrics.md)。

一次试探保持新参数两轮，按两轮首次确认字节总量除以总耗时计算吞吐。保留条件为吞吐提高至少 5%、评估时最近有效 ACK 的 P95 至多为基线的 1.2 倍、试探期间新增 BUSY 和预算失败均为零。评估后进入两轮冷却。跨轮延迟约束的后续工作见[开发计划](roadmap.md)。

压力事件优先处理：撤销当前试探，再将窗口减半至下限，进入两轮冷却。已有块继续持有预算，实际发送并发遵循收缩后的窗口。

## 策略版本

| 规则 | v1（默认） | v2 |
| --- | --- | --- |
| 调节维度 | 窗口、压缩等级、块大小 | 窗口、块大小；压缩固定 |
| 压力信号 | 认证 BUSY，或完整轮 queueShare > 0.25 | 认证 BUSY |
| 升窗候选 | 窗口占满比例 ≥0.8，输入仍在继续且预算充足 | 同 v1 |
| 块大小减半 | 本轮出现重试 | 同 v1 |
| 块大小加倍 | 窗口占满比例 ≥0.8，queueShare ≤0.1 | 窗口占满比例 ≥0.8 |
| 压缩候选 | 忙碌比例 ≥0.8 时降一级；≤0.5、窗口占满 ≥0.8、压缩比 ≤0.9 时升一级 | 保持初始等级 |

每次只试探一个可行维度，所有候选限制在已认证范围内。观测不足时继续收集样本并保持参数，短传输使用初始配置。

## 配置

源配置设置 `scheduling=FEEDBACK`，通过 `policyVersion=1` 或 `2` 选择规则。默认版本为 1。`chunkBytes`、`zstdLevel` 和 `initialWindow` 指定初值，`inFlightChunks` 指定窗口上限；省略 initialWindow 时使用上限。FIXED 使用 inFlightChunks 作为固定窗口。

策略版本由源配置选择，两端须支持所请求版本，接受结果绑定同一版本。v2 的设计与实验协议见[策略说明](policy-v2.md)。

## 实验

[二维策略比较](experiments/policy-v2/README.md)在 sink/journal 诊断中观察到 v2 相对 v1 的中位完成时间下降 20.0% / 16.5%，相对同场景固定对照的时间代价为 182.7% / 53.3%。[窗口研究](experiments/window-adaptation-v1/README.md)隔离块大小和压缩因素，分析初值敏感性、压力退让与容量恢复。两项研究均保留固定配置对照、全部样本及配置范围。
