# 二维反馈策略：设计与实验协议

v2 固定压缩等级，将控制集中在窗口与块大小。实现规则见[反馈调度](feedback.md)，18 次对照的结果见[实验报告](experiments/policy-v2/README.md)。

## 设计依据

完整周期诊断中，压缩维度的六次评估均回退。二维策略只试探窗口与块大小。queueShare、persistShare 用于诊断，认证 BUSY 触发压力退让。策略通过 Open 的 policyVersion 显式选择，默认版本为 1。

每轮至少 2 秒、16 个有效 ACK；一次试探评估两轮、冷却两轮。窗口满载且输入继续、预算充足时尝试升窗；块大小根据重试和满载情况调整。候选受已认证区间限制，已有块保持原描述与材料。

## 对照协议

| 项目 | 设置 |
| --- | --- |
| 策略 | FULL-v1、V2、固定 1 MiB / window 4 / level 3 |
| 场景与重复 | sink、journal；各 3 次，共 18 次 |
| 输入 | 512 MiB 混合数据，沿用控制周期诊断输入 |
| 动态参数 | 块 256 KiB–1 MiB；窗口 1–4；初始 256 KiB / window 1 / level 3 |
| JVM | 每次独立进程，4 个可用处理器，堆 128–768 MiB |
| 资源 | 每端字节预算 512 MiB；各组相同 Limits、安全与持久化路径 |

实验比较策略简化后的完成时间与试探成本。固定组采用表中的配置；原五策略研究的 B1 通过独立训练选择。

## 验证与数据处理

版本协商、固定压缩、两维轮换、压力中止、评估保留/回退及旧块稳定性由回归测试覆盖。每次实验检查完整性、许可归零及动态组两维的完整评估。遇到正确性或进程异常时停止矩阵，保存完整记录。策略顺序按重复轮次旋转，完整结果与中断记录随报告保存。

后续性能评测使用独立冻结的训练与评测协议。BUSY 的原因区分和恢复效率是[下一阶段研究](roadmap.md)的重点。
