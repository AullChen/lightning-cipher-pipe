# 接收端容量变化下的窗口反馈研究

窗口反馈在三轮对照中均降低了初始窗口敏感性。 在相同的 4 → 1 → 4 接纳容量变化下，两种自适应初值的配对耗时差异为 0.81%–14.87%，固定窗口 1 与 4 的差异为 53.85%–68.30%。15 次传输均完成，并通过完整性与资源检查。相对每轮最佳实测固定窗口，自适应的额外耗时为 7.0%–41.7%；轨迹分析将这一代价与容量恢复阶段的低窗口运行和重复退让联系起来。

## 研究问题与公平对照

研究问题是：**发送端通过在线反馈选择窗口时，能否降低接收端容量变化下的初值敏感性，并将耗时控制在最佳实测固定窗口的 10% 以内？** 初值敏感性衡量不同起始窗口造成的耗时差异。

实验协议在测量前冻结于 `5d419ef`，[方法整理与计量注释](../../window-study-protocol.md)提供当前阅读入口；测量源码为 `ace9ad8`，逐文件摘要见 [manifest.json](manifest.json)。测量使用既有 v2 控制器与固定阈值。

| 对照 | 窗口规则 | 其他参数 |
| --- | --- | --- |
| F1 / F2 / F4 | 固定 1 / 2 / 4 | 全部固定 256 KiB 块、ZSTD 3 |
| A1 / A4 | v2；初始 1 / 4，范围 1–4 | 与固定组相同，块大小与压缩不参与试探 |

每组 3 次独立 JVM，按重复轮次旋转顺序，共 15 次。各组使用同一 256 MiB 混合输入和相同安全、存储、预算与限额，每次均为 1024 块；块数、输入和压缩保持一致，仅比较窗口选择。输入种子 104729，交替 64 KiB 零字节与伪随机数据，SHA-256 为 `9669d60252470a87eab8042acbfd820696fb4fc52a7281140242ddfd53a59cc0`。

实验专用接纳闸门在调用 transfer 的共同时间原点后，0–12 s 允许 4 个并发块、12–28 s 允许 1 个、28 s 后恢复 4 个；降容前已接纳请求自然完成。发送端仅通过认证 BUSY 和 Retry-After 1 观察压力。每块真实 FileSink 载荷写入后额外等待 80 ms，仍执行持久化与 Finish 重读校验。即使忽略其他开销，前 28 s 最多完成 800 块，因此所有策略都会经历两次变化。该模型隔离接纳能力变化，便于观察窗口响应。

## 耗时与初值敏感性

完成时间包含连接、Open、发送、对账、退避及 Finish 验证；独立 SHA-256 复核在计时之外。相对差异使用**同一轮最快的 F1/F2/F4**，三轮均为 F4。该配置是测量后的比较参考，发送端按各自固定规则或在线反馈运行。

| 策略 | 耗时中位数 (s) | 三次范围 (s) | 相对该轮最佳固定耗时：r0 / r1 / r2 |
| --- | ---: | ---: | --- |
| F1 | 98.381 | 96.619–98.862 | +53.8% / +68.3% / +57.7% |
| F2 | 66.555 | 66.494–70.616 | +4.0% / +20.2% / +8.6% |
| F4 | 61.287 | 58.740–63.947 | +0.0% / +0.0% / +0.0% |
| A1 | 70.304 | 68.996–72.436 | +7.9% / +23.3% / +14.7% |
| A4 | 68.445 | 66.911–83.210 | +7.0% / +41.7% / +9.2% |

初值敏感性为 `abs(T1-T4)/min(T1,T4)`。两种自适应初值完整报告，三个重复采用描述性统计。

| 重复 | 固定窗口端点敏感性 | 自适应初值敏感性 |
| --- | ---: | ---: |
| 0 | 53.85% | 0.81% |
| 1 | 68.30% | 14.87% |
| 2 | 57.65% | 5.07% |

预设的初值敏感性条件在三轮均成立；耗时条件要求两种初值在全部三轮都处于最佳固定的 10% 以内，本矩阵的额外耗时范围为 7.0%–41.7%。后续研究针对这一恢复效率差距展开，见[研究计划](../../roadmap.md)。

## 窗口响应与吞吐变化

![容量、实际窗口、确认吞吐和 ACK 延迟的共同时间轴](mechanism.png)

图 1（[SVG](mechanism.svg)）：测量前选定的第 0 轮。A 为外部施加的接纳上限，B 为源端实际窗口，C 为确认字节差分形成的 1 s 吞吐，D 为最近 64 个有效 ACK 的滚动 P95。阴影表示低容量阶段；时间轴一致，窗口保留原始阶梯变化。ACK 指标取首次发送获得的有效确认样本，按最近 64 个样本滚动计算；确认吞吐计量应用层持久确认进度。曲线包含验证尾段，响应判定另在确认完全部输入时截止。全部重复的压缩原始轨迹见 [traces](traces/)。

第 0 轮在 12 s 降容后，A1/A4 均约在 13.25 s 观察到窗口降至 1；低容量阶段它们又尝试升至 2，并被新的 BUSY 中止。28 s 恢复容量后，窗口先在约 33.25/33.50 s 升至 2，到 43.50/44.00 s 才首次升至至少 3 并维持两秒。低容量阶段 A1/A4 的三次中位确认吞吐为 2.09/2.16 MiB/s，高于 F4 的 0.27 MiB/s；恢复阶段则为 4.16/3.95 MiB/s，低于 F4 的 5.64 MiB/s。这个滞后与现有每轮至少 16 个有效 ACK、2 s、两轮评估和两轮冷却的规则相符；恢复阶段仍会出现非闸门 BUSY，触发撤销试探和再次降窗，使确认吞吐回落。因此决策函数计算很短，仍可能付出较长的低窗口运行与退避成本。滚动有效 ACK P95、BUSY 和退避时间分别描述不同成本，完整表现由总完成时间衡量。后续通过消融实验分别检验这些规则的影响。

响应定义在测量前确定：降容后首次窗口 ≤1、恢复后首次窗口 ≥3，均须持续至少 2 s。表中给出相对条件变化时刻的延迟；首次持续响应与之后的窗口轨迹分别报告。观察截止于确认完整输入的首个样本，验证尾段单独计时。

| 样本 | 降容响应 | 恢复响应 | 源端观测 BUSY / 闸门拒绝数 |
| --- | --- | --- | ---: |
| A1-r0 | 1.25 s | 15.50 s | 5 / 4 |
| A4-r0 | 1.25 s | 16.00 s | 7 / 5 |
| A1-r1 | 1.25 s | 右删失；观察 41.00 s | 5 / 3 |
| A4-r1 | 变化前已在该区间 | 右删失；观察 53.75 s | 10 / 3 |
| A1-r2 | 1.25 s | 16.25 s | 5 / 5 |
| A4-r2 | 1.25 s | 右删失；观察 37.50 s | 6 / 4 |

“右删失”表示观察截至确认完整输入时结束，恢复事件时间记为大于该观察长度。A4-r1 在 12 s 前已处于窗口 1，故降容响应记为“变化前已在该区间”。恢复阶段其源端观测到 10 次 BUSY，闸门记录 3 次拒绝；F2-r2 的两个计数分别为 12 / 14。源端响应与闸门拒绝处于不同观测点，按各自口径列出。后续增加原处理器原因计数，以分离锁、预算和槽位压力。完整六份响应结果与第 0 轮图共同描述窗口行为。

## 复现与测量环境

运行和绘图命令见 [benchmarks README](../../../benchmarks/README.md#changing-receiver-capacity-window-only-research-study)。[results.json](results.json)保留全部 15 个结果，[summary.json](summary.json)包含逐次响应、分阶段吞吐、采样间隔、配对比较和判定。所有输出摘要一致、每次 1024 块 / 256 MiB、双方租约及接纳计数归零；正式矩阵一次完成。完整 Java 构建通过 379 项测试；分析另有 9 项回归覆盖截断、持续响应和联合成功门禁。最大实际采样间隔为 0.260 s，响应时间受约 250 ms 的观测粒度限制。

测量环境：Intel Core i9-13900HX（24 核 / 32 线程）、约 16 GiB 内存、Windows 11 Pro 10.0.22621、NTFS / KIOXIA EXCERIA PLUS G3 NVMe SSD、Microsoft OpenJDK 17.0.7。源与目标位于同一 JVM，通过真实 TLS 1.3 mTLS / HPKE / FileSink 直连；JVM 4 个可用处理器、堆 128–768 MiB，每端缓冲 512 MiB、元数据 8 MiB。测量时段专用于本矩阵，系统采用常规共享调度。证据覆盖一种数据分布、一条容量轨迹、三个重复和两个初始窗口端点。

## 后续改进

后续以预设的 ≤10% 时间代价为目标，缩短当前 7.0%–41.7% 的额外耗时。先分类短暂内部拒绝与持续接纳压力，再分别设计消融实验，在测量前固定方案，比较采样、冷却与恢复升窗的作用。

扩展到更多输入、容量轨迹、初始窗口与独立重复，补充 WAN、跨主机、多任务竞争和外部方法对照。另行开展使用研究衡量实际调参成本，通过独立的运行期测量区分采样开销和控制开销。
