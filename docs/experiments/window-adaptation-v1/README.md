# 接收端容量变化下的窗口反馈研究

**现有 v2 降低了初始窗口选择带来的耗时差异，但未达到预先约定的耗时目标。** 在相同的 4 → 1 → 4 接纳容量变化下，两种自适应初值的配对耗时差异都小于固定窗口 1 与 4 的差异；然而，自适应相对每轮最佳固定窗口的额外耗时为 7.0%–41.7%，没有全部落入 10% 范围。15 次传输均完成且通过完整性和资源门禁。这支持一个有限结论：反馈缓解了选错较小窗口的代价，但其恢复速度与抗短暂拒绝能力仍不足以替代合适的固定配置。

阅读顺序：研究问题与公平对照 → 配对耗时 → 一张机制图与响应时间 → 额外成本 → 复现、限制与证据审查。

## 研究问题与公平对照

研究问题收窄为：**在发送端事先不知道合适窗口、接收端接纳并发能力发生变化时，现有轻量反馈能否降低初始配置敏感性，并将传输耗时控制在最佳实测固定窗口的 10% 以内？** “减少人工调参”在此仅通过初始窗口敏感性衡量，没有开展开发者使用研究。

[实验协议](../../window-adaptation-protocol.md)在测量前冻结于 `5d419ef`；测量源码为 `ace9ad8`，逐文件摘要见 [manifest.json](manifest.json)。此次只增加实验工具和分析，不修改生产控制器、阈值或默认策略。

| 对照 | 窗口规则 | 其他参数 |
| --- | --- | --- |
| F1 / F2 / F4 | 固定 1 / 2 / 4 | 全部固定 256 KiB 块、ZSTD 3 |
| A1 / A4 | v2；初始 1 / 4，范围 1–4 | 与固定组相同，块大小与压缩不参与试探 |

每组 3 次独立 JVM，按重复轮次旋转顺序，共 15 次。各组使用同一 256 MiB 混合输入和相同安全、存储、预算与限额，每次均为 1024 块；不存在动态组靠改变块数取得优势的混杂因素。输入种子 104729，交替 64 KiB 零字节与伪随机数据，SHA-256 为 `9669d60252470a87eab8042acbfd820696fb4fc52a7281140242ddfd53a59cc0`。

实验专用接纳闸门在调用 transfer 的共同时间原点后，0–12 s 允许 4 个并发块、12–28 s 允许 1 个、28 s 后恢复 4 个；降容前已接纳请求自然完成。发送端不知道轨迹，只看到认证 BUSY 和 Retry-After 1。每块真实 FileSink 载荷写入后额外等待 80 ms，仍执行持久化与 Finish 重读校验。即使忽略其他开销，前 28 s 最多完成 800 块，因此所有策略都会经历两次变化。这是接纳能力的受控模拟，不是完整的生产磁盘或网络模型。

## 耗时与初值敏感性

完成时间包含连接、Open、发送、对账、退避及 Finish 验证；独立 SHA-256 复核在计时之外。相对差异使用**同一轮最快的 F1/F2/F4**，三轮均为 F4。该事后参考不能当成发送端事先已知的最佳配置。

| 策略 | 耗时中位数 (s) | 三次范围 (s) | 相对该轮最佳固定耗时：r0 / r1 / r2 |
| --- | ---: | ---: | --- |
| F1 | 98.381 | 96.619–98.862 | +53.8% / +68.3% / +57.7% |
| F2 | 66.555 | 66.494–70.616 | +4.0% / +20.2% / +8.6% |
| F4 | 61.287 | 58.740–63.947 | +0.0% / +0.0% / +0.0% |
| A1 | 70.304 | 68.996–72.436 | +7.9% / +23.3% / +14.7% |
| A4 | 68.445 | 66.911–83.210 | +7.0% / +41.7% / +9.2% |

初值敏感性为 `abs(T1-T4)/min(T1,T4)`。两种自适应初值全部报告，不事后挑选较快者。三个重复只能提供描述性证据，不宣称统计显著。

| 重复 | 固定窗口端点敏感性 | 自适应初值敏感性 |
| --- | ---: | ---: |
| 0 | 53.85% | 0.81% |
| 1 | 68.30% | 14.87% |
| 2 | 57.65% | 5.07% |

“各轮初值敏感性降低”通过；“两种初值在全部三轮都不超过最佳固定耗时的 10%”失败，故联合目标失败。较 F1 更快不能替代与 F2、F4 的公平比较，也不改变此前联合策略的负面结论。

## 一张图与机制解释

![容量、实际窗口、确认吞吐和 ACK 延迟的共同时间轴](mechanism.png)

图 1（[SVG](mechanism.svg)）：测量前选定的第 0 轮。A 为外部施加的接纳上限，B 为源端实际窗口，C 为确认字节差分形成的 1 s 吞吐，D 为最近 64 个有效 ACK 的滚动 P95。阴影表示低容量阶段；时间轴一致，窗口不平滑。ACK 指标排除重试样本，不是区间延迟分位数或网络 RTT；确认吞吐也不是网卡线速。曲线包含验证尾段，响应判定另在确认完全部输入时截止。全部重复的压缩原始轨迹见 [traces](traces/)。

**机制解释：快速退让并不保证快速、稳定恢复。** 第 0 轮在 12 s 降容后，A1/A4 均约在 13.25 s 观察到窗口降至 1；低容量阶段它们又尝试升至 2，并被新的 BUSY 中止。28 s 恢复容量后，窗口先在约 33.25/33.50 s 升至 2，到 43.50/44.00 s 才首次升至至少 3 并维持两秒。低容量阶段 A1/A4 的三次中位确认吞吐为 2.09/2.16 MiB/s，高于 F4 的 0.27 MiB/s；恢复阶段则为 4.16/3.95 MiB/s，低于 F4 的 5.64 MiB/s。这个滞后与现有每轮至少 16 个有效 ACK、2 s、两轮评估和两轮冷却的规则相符；恢复阶段仍会出现非闸门 BUSY，触发撤销试探和再次降窗，使确认吞吐回落。因此决策函数计算很短，仍可能付出较长的低窗口运行与退避成本。滚动有效 ACK P95 无法单独表达被拒绝请求和退避损失，不能用较低 ACK 延迟证明总体传输更优。这些是轨迹与实现共同支持的机制解释，尚未通过消融实验分离各规则的因果贡献。

响应定义在测量前确定：降容后首次窗口 ≤1、恢复后首次窗口 ≥3，均须持续至少 2 s。表中给出相对条件变化时刻的延迟；首次持续响应不保证之后一直保持。观察截止于确认完整输入的首个样本，不把验证尾段算作恢复成功。

| 样本 | 降容响应 | 恢复响应 | 源端观测 BUSY / 闸门拒绝数 |
| --- | --- | --- | ---: |
| A1-r0 | 1.25 s | 15.50 s | 5 / 4 |
| A4-r0 | 1.25 s | 16.00 s | 7 / 5 |
| A1-r1 | 1.25 s | 未达到；观察 41.00 s | 5 / 3 |
| A4-r1 | 变化前已在该区间 | 未达到；观察 53.75 s | 10 / 3 |
| A1-r2 | 1.25 s | 16.25 s | 5 / 5 |
| A4-r2 | 1.25 s | 未达到；观察 37.50 s | 6 / 4 |

A4-r1 在 12 s 前已降至 1，因此不能把它记作零延迟感知了降容。该样本恢复阶段直到观察截止仍未满足窗口 ≥3；其源端观测到 10 次 BUSY，而闸门记录 3 次拒绝，说明还存在非闸门拒绝。两个计数分别发生在源端收到响应与接收端拒绝请求时，不能假定每次拒绝都被源端解析为 BUSY；例如 F2-r2 的两个计数为 12 / 14。因此差值不能作为内部 BUSY 的精确计数。冻结协议所称“分别记录”实际是这两个观测点，未直接统计原处理器的 BUSY；当前证据也不能认定具体是哪把锁或存储操作导致拒绝。第 0 轮图并不能代表全部样本稳定恢复。

## 额外成本与完整控制周期

| 策略 | 进程 CPU 中位数 (s) | 决策计时中位数 (ms) | 重试次数 r0 / r1 / r2 | 重试帧中位数 (MiB) |
| --- | ---: | ---: | --- | ---: |
| F1 | 2.375 | 0.000 | 0 / 0 / 0 | 0.000 |
| F2 | 2.859 | 0.000 | 15 / 18 / 14 | 1.878 |
| F4 | 3.609 | 0.000 | 44 / 37 / 41 | 5.132 |
| A1 | 2.469 | 1.329 | 7 / 6 / 7 | 0.876 |
| A4 | 3.484 | 1.470 | 9 / 12 / 8 | 1.127 |

CPU 覆盖同一 JVM 中的源端、目标端和采样线程。决策计时为 `System.nanoTime()` 包围控制调用的累计经过时间；冻结协议将其称为“decision CPU nanoseconds”，这里纠正术语，**它不是线程 CPU 测量**，也不包括全部采样、对账和网络成本。重试帧字节是应用提交重试的加密帧，不是 TCP 重传或实际网卡字节。各组使用同一采样工具，工具自身开销未单独隔离。以上成本不能由单项相减解释为纯算法开销。

| 策略（3 次合计） | 启动 | 完整两轮评估 | 保留 | 评估后回退 | 压力中止 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1 | 23 | 8 | 8 | 0 | 13 |
| A4 | 23 | 5 | 5 | 0 | 17 |

未完整评估的试探和压力中止均保留，不把仅仅升窗算作控制收益。`启动 - 完整评估 - 压力中止` 是传输结束时尚未完成的试探数；评估后回退为零也不意味着没有压力引发的参数回退。

## 复现与证据边界

运行和绘图命令见 [benchmarks README](../../../benchmarks/README.md#changing-receiver-capacity-window-only-research-study)。[results.json](results.json)保留全部 15 个结果，[summary.json](summary.json)包含逐次响应、分阶段吞吐、采样间隔、配对比较和判定。所有输出摘要一致、每次 1024 块 / 256 MiB、双方租约及接纳计数归零；无正式测量失败或补跑。完整 Java 构建通过 379 项测试；分析另有 9 项回归覆盖截断、持续响应和联合成功门禁。最大实际采样间隔为 0.260 s，响应时间受约 250 ms 的观测粒度限制。

环境与限制：Intel Core i9-13900HX（24 核 / 32 线程）、约 16 GiB 内存、Windows 11 Pro 10.0.22621、NTFS / KIOXIA EXCERIA PLUS G3 NVMe SSD、Microsoft OpenJDK 17.0.7，源端和目标端同一 JVM，实际 TLS 1.3 mTLS / HPKE / FileSink，无链路代理；JVM 4 个可用处理器、堆 128–768 MiB，每端缓冲 512 MiB、元数据 8 MiB。测量期间未并行构建或运行项目负载测试，但不代表操作系统和硬件完全隔离。本实验只覆盖一种数据分布、一条接纳变化轨迹、三个重复及初始窗口端点；没有 WAN、跨主机、多任务竞争、更多初始值或最新研究方法的比较，不能声称学术创新、泛化收益或生产性能保证。

本次研究产出是可复现的窄问题、隔离变量的实验和可解释的失败证据。下一项可检验假设是：区分短暂内部拒绝与持续接纳不足，是否能减少恢复阶段的重复退让。该假设仍需更细的原因观测和独立冻结的消融实验；本报告不据此调参或新增策略版本，默认 v1 与可选 v2 的交付范围保持不变。

## 五维自审

- **贡献**：问题是否足够具体？是，聚焦未知窗口与变化接纳能力；贡献限于问题定义、评估工具和失败机制证据。
- **清晰度**：指标是否混淆？区分完成时间、数据阶段、滚动有效 ACK P95、确认吞吐和决策经过时间；图与表使用同一命名。
- **实验强度**：是否只挑弱基线？否，比较三个固定窗口、两个动态初值，输入、块数、压缩和资源相同；最佳固定仅是事后参考。
- **完整性**：是否隐藏失败与截断？否，保留 15 次结果、六个动态响应和全部轨迹，未恢复标注观察时长，不丢弃不利轮次。
- **方法可靠性**：是否把相关性当因果或过度推广？没有宣称因果消融、统计显著或学术新颖性；单轨迹、三次重复和内部 BUSY 未分类仍是主要限制。
