# 可选反馈策略 v2 对照诊断

## 结果与判断

本矩阵中 v2 相对 v1 的六个配对样本均更快，sink/journal 中位完成时间分别降低 20.0% / 16.5%。FIXED 使用固定参数作为对照。

18 次全部完成，摘要一致且两端许可归零。完整周期、固定压缩和计数一致性检查全部通过。完整数据见 [results.json](results.json)、[summary.json](summary.json) 和 [manifest.json](manifest.json)；中断批次见 [interrupted/results.json](interrupted/results.json) 与 [状态](interrupted/status.json)。

## 块数量与 CPU

下列均为三次中位数。CPU 记录传输期间双端与代理所在进程的 CPU 时间。

| 场景 | 策略 | 块数 | CPU 秒数 |
| --- | --- | ---: | ---: |
| sink | FULL | 1079 | 5.734 |
| sink | V2 | 866 | 5.078 |
| sink | FIXED | 512 | 3.297 |
| journal | FULL | 868 | 4.859 |
| journal | V2 | 725 | 5.141 |
| journal | FIXED | 512 | 4.531 |

动态组之间的块数差异意味着平均块大小不同。按块注入 80 ms 延迟时，减少提交次数与较短耗时相符，各机制的贡献可通过后续轨迹采样与消融进一步分离。固定组始终发送 512 个 1 MiB 块，动态组从小块、小窗口启动；该成本比较对应本次按块注入延迟的混合输入场景。

## 后续改进

v2 保持显式选择，默认版本为 v1。后续以本批 FIXED 耗时为参考，优化启动窗口、试探和冷却规则，并通过独立消融区分压缩固定、压力信号和瞬时 BUSY 的作用。新增实验在测量前固定训练与评测协议，覆盖短输入、阶跃链路、8 MiB 块上界及双主机场景，结果与既有报告分别归档。

## 冻结方法

实现提交 `e3c5ec4`，完整验证通过 378 项测试，失败、错误、跳过均为 0。默认 policyVersion 仍为 1。v2 显式选择版本 2，固定协商后的初始压缩等级，只轮换窗口和块大小；queueShare 不参与压力触发及块候选判断，认证 BUSY 仍触发撤销试探、降窗和两轮冷却。采样有效性、每轮 16 ACK / 2 秒、两轮评估、5% goodput / 1.2 倍 ACK P95 判据不变。

每场景各运行 FULL、V2、FIXED 三组，各三次；按重复轮次旋转组顺序，共 18 次。场景为载荷写入后延迟 80 ms 的 sink，以及持有回执日志锁时延迟 80 ms 的 journal。每次独立 JVM，Windows 11 / Microsoft OpenJDK 17.0.7，4 个可用处理器、堆 128–768 MiB，每端字节预算 512 MiB、元数据预算 8 MiB。两端及 TLS 代理同一 JVM，测量时段专用于本矩阵，CPU 由操作系统共享调度。

输入均为同一 512 MiB 混合数据，种子 104729，交替 64 KiB 零字节与伪随机字节，SHA-256 为 `161018c4871f690ca5687ec262efb5eed7a1258b855ad05d26002a38212bd27c`。动态组初始为 256 KiB/window 1/level 3，范围为 256 KiB–1 MiB/window 1–4/level 1–5；v2 实际固定 level 3。固定组为 1 MiB/window 4/level 3。三组 Limits 相同：最大明文 8 MiB、帧 9 MiB、maxChunks=4096、槽位 16，预算约束后的有效窗口上限为 4。

FIXED 使用本次声明的参数；原研究 B1 的训练选择见对应报告。原始数据由 `benchmarks/policy_v2.py` 保留；单次 300 秒截止，完整性或许可不变量失败即停止。两个动态组的每条成功传输都必须完成窗口和块大小的两轮评估，v2 压缩试探必须为 0。只有完整矩阵才能判定此门禁通过。

报告采用完成时间中位数及逐次配对差异。v1 对照衡量简化后的总体变化，FIXED 对照衡量动态配置的时间成本；压缩固定与压力规则作为一个策略版本整体评估。

## 复现

JDK 17、Python 3.10+，设置 JAVA_HOME：

```powershell
.\mvnw.cmd -Pbenchmarks package -DskipTests
python benchmarks/policy_v2.py benchmarks/results/policy-v2-new
```

输出使用新建目录。查看该目录 results.json、manifest.json、summary.json 及每次日志。`python benchmarks/policy_v2.py EXISTING_OUTPUT --summarize` 直接读取既有样本重算描述性汇总。扩展实验按后续计划另行冻结协议。
