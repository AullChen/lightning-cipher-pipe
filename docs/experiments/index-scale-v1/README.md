# 大索引配额边界验证

本验证覆盖大索引近满恢复、分页对账与精确配额处理。检查对象为实际 `ReceiptLedger` 和 `FileSink`，每种规模独立启动一个 JVM；源描述符与目标索引在同一进程中同时存在。

## 方法

选择 65,536 和 1,000,000 槽位。每端元数据预算精确设为 `52 × maxChunks` 字节；源紧凑数组占 `49 × maxChunks`，目标槽位和有序索引占 `52 × maxChunks`。这些数字计量索引数组；对象头、临时对象与 JVM 开销由 RSS 另行观测。

以真实 FileSink 建立 Open 控制记录并关闭，再由确定性夹具写入 `maxChunks - 1` 条完整 CRC32C receipt 记录和对应载荷，分别 force。每条只含一个字节，值为索引的低八位，摘要为该字节的 SHA-256。夹具按存储格式直接构造近满日志，前置记录直接按持久格式生成，真实 commit 用于最后一槽及其幂等重放。1 字节分块用于隔离存储层行为，SDK 的常规分块范围见接入指南。

随后使用生产实现执行以下断言，任何失败均使进程非零退出：

1. 源历史与目标 Open 的元数据预算少一字节时拒绝；拒绝的 Open 不创建 UUID 任务目录。
2. 恢复近满日志，核对恢复数量；每页最多 256 条，通过源 `ReceiptLedger.reconcile` 检查全部描述符与已确认历史。
3. 经真实 `FileSink.commit` 提交最后一槽并再次重复提交，确认只有一条新日志记录；源端重复确认不增加字节计数。
4. 尝试索引 `maxChunks`：源端拒绝继续分配，目标返回 `LIMIT_EXCEEDED`，载荷长度与已提交计数保持不变。
5. 关闭并重开满索引，再次遍历全部 receipt，逐字节校验持久载荷及 EOF；删除最后一页中的历史 ACK 构造反例，必须返回 `UNKNOWN_COMMIT`。

另有 257 槽位跨页冒烟，覆盖非整页尾部，其证据单独保留在 [smoke.json](smoke.json)。每组执行记录完整保存。

## 结果

Java 17.0.7 / Windows 11；两组 JVM 均报告 32 个可用处理器。固定 `-Xms64m -Xmx256m`，NMT summary；每组执行一次，恢复时间用于描述本次操作耗时。

| 槽位上限 | 预填 receipt | 两轮核对页数 | 每端元数据预算（字节） | 峰值 RSS（MiB） | 近满恢复 / 满索引重开（秒） | 结果 |
| ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 65,536 | 65,535 | 512 | 3,407,872 | 110.2 | 0.330 / 0.308 | PASS |
| 1,000,000 | 999,999 | 7,814 | 52,000,000 | 272.2 | 4.219 / 5.859 | PASS |

全部案例成功，无 OOM、超时或意外退出。百万槽位案例分别验证 999,999 和 1,000,000 条记录的恢复，持久日志最终为 68,000,000 字节，完整载荷为 1,000,000 字节。两轮对账时源端保留全部确认历史；最后的越界尝试没有增加载荷或 receipt 数量。

RSS 为操作系统进程高水位和 50 ms 采样中的最大值，包含两端、恢复临时分配和 JVM；允许高于 256 MiB 堆上限。`peakHeapPoolSum` 是各堆池峰值之和，按各池独立峰值聚合；NMT native 是退出快照减去 Java heap，按 NMT 的退出时观测口径统计。完整观测、JVM 参数、基线提交及工具 SHA-256 见 [evidence.json](evidence.json)。基线哈希标识本次使用的生产实现版本，新增工具由文件摘要标识。

## 复现

使用 JDK 17、Python 3.10+，从源码根目录运行；Windows 将 Wrapper 改为 `mvnw.cmd`：

```sh
./mvnw -Pbenchmarks package -DskipTests
python benchmarks/index_scale.py
```

默认执行两组并将日志、生成的存储夹具及汇总写入忽略的 `benchmarks/results/index-scale`，已有目录拒绝覆盖。需要独立复现时以 `--output` 指向一个尚不存在的目录。较小冒烟可使用 `--slots 257`。每组最多 600 秒，失败记录保留；脚本要求可用 RSS 与 NMT 观测，缺测状态显式记录。RSS 采样当前实现适用于 Windows 或提供 `/proc/<pid>/status` 的系统，平台验证范围据此记录。
