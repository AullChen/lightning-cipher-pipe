# 大索引配额边界验证

本验证补充 V22 的大索引近满恢复证据，不是吞吐对照实验，也不改变反馈策略结论。检查对象为实际 `ReceiptLedger` 和 `FileSink`，每种规模独立启动一个 JVM；源描述符与目标索引在同一进程中同时存在。

## 方法

选择 65,536 和 1,000,000 槽位。每端元数据预算精确设为 `52 × maxChunks` 字节；源紧凑数组占 `49 × maxChunks`，目标槽位和有序索引占 `52 × maxChunks`。这些数字不含对象头、临时对象和 JVM 开销，不能当作 RSS 上限。

以真实 FileSink 建立 Open 控制记录并关闭，再由确定性夹具写入 `maxChunks - 1` 条完整 CRC32C receipt 记录和对应载荷，分别 force。每条只含一个字节，值为索引的低八位，摘要为该字节的 SHA-256。夹具按存储格式直接构造近满日志，**没有执行这些前置块的网络认证和逐块持久提交**，不提供百万次网络发送或刷盘性能证据。1 字节分块仅供存储层测试，不是 SDK 启动器的正常分块参数。

随后使用生产实现执行以下断言，任何失败均使进程非零退出：

1. 源历史与目标 Open 的元数据预算少一字节时拒绝；拒绝的 Open 不创建 UUID 任务目录。
2. 恢复近满日志，核对恢复数量；每页最多 256 条，通过源 `ReceiptLedger.reconcile` 检查全部描述符与已确认历史。
3. 经真实 `FileSink.commit` 提交最后一槽并再次重复提交，确认只有一条新日志记录；源端重复确认不增加字节计数。
4. 尝试索引 `maxChunks`：源端拒绝继续分配，目标返回 `LIMIT_EXCEEDED`，载荷长度与已提交计数保持不变。
5. 关闭并重开满索引，再次遍历全部 receipt，逐字节校验持久载荷及 EOF；删除最后一页中的历史 ACK 构造反例，必须返回 `UNKNOWN_COMMIT`。

另有 257 槽位跨页冒烟，覆盖非整页尾部，其证据单独保留在 [smoke.json](smoke.json)。没有删除失败结果或重复执行直到成功。

## 结果

Java 17.0.7 / Windows 11；两组 JVM 均报告 32 个可用处理器。固定 `-Xms64m -Xmx256m`，NMT summary；一次运行每组，不作统计显著性或速度比较。恢复时间用于定位本次操作耗时，不是性能承诺。

| 槽位上限 | 预填 receipt | 两轮核对页数 | 每端元数据预算（字节） | 峰值 RSS（MiB） | 近满恢复 / 满索引重开（秒） | 结果 |
| ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 65,536 | 65,535 | 512 | 3,407,872 | 110.2 | 0.330 / 0.308 | PASS |
| 1,000,000 | 999,999 | 7,814 | 52,000,000 | 272.2 | 4.219 / 5.859 | PASS |

全部案例成功，无 OOM、超时或意外退出。百万槽位案例分别验证 999,999 和 1,000,000 条记录的恢复，持久日志最终为 68,000,000 字节，完整载荷为 1,000,000 字节。两轮对账时源端保留全部确认历史；最后的越界尝试没有增加载荷或 receipt 数量。

RSS 为操作系统进程高水位和 50 ms 采样中的最大值，包含两端、恢复临时分配和 JVM；允许高于 256 MiB 堆上限。`peakHeapPoolSum` 是各堆池峰值之和，不是同步峰值；NMT native 是退出快照减去 Java heap，不是峰值或所有原生分配的总账。完整观测、JVM 参数、基线提交及工具 SHA-256 见 [evidence.json](evidence.json)。基线哈希表示未修改生产实现所在版本，新增工具由文件摘要标识。

## 复现

使用 JDK 17、Python 3.10+，从源码根目录运行；Windows 将 Wrapper 改为 `mvnw.cmd`：

```sh
./mvnw -Pbenchmarks package -DskipTests
python benchmarks/index_scale.py
```

默认执行两组并将日志、生成的存储夹具及汇总写入忽略的 `benchmarks/results/index-scale`，已有目录拒绝覆盖。需要独立复现时以 `--output` 指向一个尚不存在的目录。较小冒烟可使用 `--slots 257`。每组最多 600 秒，失败记录保留；脚本要求可用 RSS 与 NMT 观测，不把缺测当零。RSS 采样当前实现适用于 Windows 或提供 `/proc/<pid>/status` 的系统，其他平台不能据此声称已验证。

## 边界

这补齐了百万槽位下的分配、顺序日志恢复、分页对账和精确配额边界；未更改协议、生产存储实现或预算公式。仍未验证百万次真实网络 Chunk、任意乱序日志的恢复成本、超百万槽位、多个任务、机器断电或其他平台。固定容量结构加上本次实测是已测范围的资源证据，不是任意输入规模的内存证明。原 [反馈实验](../feedback-v1/README.md) 保持原始数据与负面结论。
