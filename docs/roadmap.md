# 后续研究与开发

## 1. 回调关闭与评估边界

- OpenObserver 内调用 close 仍可能等待当前传输自行退出。明确回调内关闭语义，增加一个短期限回归，覆盖输入关闭和资源释放。
- 当前试探吞吐累计两轮，延迟保护读取评估末尾的滚动 P95。补充首轮恶化、次轮恢复的序列，确定跨轮延迟约束，并同步策略文档与版本语义。

验收以确定性序列和一个真实传输回归为主，随后运行完整构建。

## 2. 提高容量恢复阶段的效率

窗口研究已显示初值敏感性下降，自适应相对最佳实测固定窗口仍有 7.0%–41.7% 的耗时代价。下一项假设是：区分短暂内部拒绝与持续容量不足，能否减少恢复阶段的重复退让。

先补充接收端 BUSY 原因观测，再设计独立冻结的单因素消融。分别评估冷却时长、恢复升窗和压力判定，保持块大小、压缩、输入及持久化路径一致。每次只修改一个机制，保留全部样本。

## 3. 扩展研究证据

现有窗口研究覆盖单条容量轨迹、单一输入分布和三个重复。扩展到更多轨迹、初始窗口和独立重复，并用独立评测集检查参数敏感性。将简单窗口控制方法纳入同管线对照，报告完成时间、阶段吞吐、重试成本和响应时间。

研究主张以已完成实验为依据。比较外部方法后再讨论新颖性，跨主机实验后再讨论环境迁移能力。

## 4. 完善适配器验证

参考环境为 Windows 11 / NTFS。逐步补充 Linux 文件系统验证、跨主机传输和长时间资源观测。机器断电恢复需要独立故障实验；源进程重启后的旧偏移续传、多任务调度和业务导入可按具体需求单独设计。

每项开发使用最小相关测试与完整构建验收。性能测量与构建分开运行，失败记录与成功样本共同保存。
