# 后续研究与开发

## 回调关闭与跨轮延迟

完善 OpenObserver 回调内调用 close 的处理，使关闭请求与当前传输退出协调。增加一个短期限回归，检查输入关闭和资源释放。

当前试探吞吐累计两轮，延迟保护读取评估末尾的滚动 P95。补充首轮恶化、次轮恢复的测试序列，明确跨轮延迟约束，并同步策略文档与版本语义。这两项修改用确定性序列和真实传输回归验证，再运行完整构建。

## 容量恢复与试探效率

窗口研究中，自适应降低了初值敏感性，相对最佳实测固定窗口的额外耗时为 7.0%–41.7%。下一步检验：区分短暂内部拒绝与持续容量不足后，能否减少恢复阶段的重复退让。

先记录接收端 BUSY 的具体原因，再分别比较冷却时长、恢复升窗和压力判定的影响。每次只修改一个机制，保持块大小、压缩、输入及持久化路径一致；实验方案在测量前固定，保留全部样本。

二维策略在 sink/journal 诊断中较 v1 分别缩短 20.0% / 16.5% 的中位耗时，相对该矩阵固定对照的额外耗时为 182.7% / 53.3%。后续以固定对照为参考，优化启动配置、试探效率和恢复速度。

## 扩展实验

现有窗口研究采用一条容量轨迹、一种输入分布和三个重复。增加轨迹、初始窗口与独立重复次数，并用独立评测集检查参数敏感性。将简单窗口控制方法纳入同管线对照，比较完成时间、阶段吞吐、重试成本和响应时间。

补充运行期 CPU、原生分配与 RSS 观测。反馈继续使用最近有效 ACK 的滚动分位数，用户可感知延迟则通过完整请求分布评估。跨主机实验用于考察环境迁移，外部方法对照用于讨论新颖性。

性能测量与构建分开运行，成功和失败记录一起保存。

## 平台与恢复验证

参考环境为 Windows 11 / NTFS。补充 Linux 文件系统、网络文件系统、跨主机传输和长时间资源测试，分别开展机器断电恢复实验。完善 Linux/macOS 演示命令，并为源码构件建立可重复的发布流程。

源进程重启后的旧偏移续传、多任务调度可按具体需求单独设计。每项开发使用最小相关测试与完整构建验收。

## 密钥管理与业务接入

当前 HPKE Auth 使用授权的长期接收密钥，安全分析以该密钥的保密管理为前提。针对长期私钥泄露后的历史密文保护，评估具有前向安全目标的会话密钥方案，并制定密钥轮换、保留与销毁流程。

保持核心传输契约稳定，按接入需求设计数据库适配、业务导入事务、管理删除接口和自动保留期。管理操作先确认任务终态，再按完整数据归档流程处理。
