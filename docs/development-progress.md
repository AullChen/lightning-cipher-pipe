## 验证范围

`mvnw clean verify` 执行编译与快速测试；Windows 使用 `mvnw.cmd`。全工程包含 352 项测试，其中 17 项压缩测试、76 项真实 TLS 传输集成测试，并覆盖配置启动的双 JVM 传输。`-Pbenchmarks verify` 另运行代理字节流回归；性能矩阵通过独立 Python 入口执行，不进入快速门禁。

- V01–V03：规范编码、长度与配额、独立 Merkle 根、api/core 依赖边界。
- V04–V05：标准 HPKE Auth 向量、AAD/frame 篡改、实际 TLS 身份/SPKI、路由与密钥校验。
- V06：持久 Open、相同请求重放、冲突和过期拒绝。
- V07–V09：短写、force 后 receipt、存储边界异常、残片截断、完整 CRC 损坏、载荷缺失、根目录跨进程锁。另覆盖八个真实目标进程退出边界、恢复刷盘失败及路径逃逸拒绝。
- V10：空流、1 字节、未知长度和跨块传输，包含超过 8 MiB 的持久输出逐字节比对。
- V11：NONE/ZSTD 的高重复、高熵及空流；帧长度、尾随数据、拼接帧、窗口和输出上限、预算不足；原生调用前后的中断检查。
- V12：Finish 幂等、缺块后补交、终态写入限制；修改、截短、扩展输出或错误 Merkle 根均不能完成。
- V13–V14（并发部分）：三窗口真实 TLS 传输、阻塞写入期间的乱序完成、重复/重叠拒绝、Finish/Cancel 入场和满预算许可持有。
- V13–V15（对账部分）：假时钟退避/TTL、真实超时、提交后丢 ACK、跨 256 条分页、历史 ACK 缺失停读、满预算重封装、小帧对账预算回归、四次 BUSY 上限、Finish 响应丢失和请求帧脱离。另覆盖源控制记录的进程退出及真实双 JVM 中目标崩溃重启、存活源续传。
- V16–V17：同清单仅单个后台校验器、VERIFYING 重启、取消与完成两种获胜顺序、取消超时冻结、关闭超时保留根锁和源消费者预算；完成输出不删除。
- V18–V20：假时钟计量、64 条样本上限、缺测与去重；决策表覆盖压力优先、三维轮换、两轮合计吞吐、收益/延迟/预算回退、冷却、边界和无效观测；真实 TLS 验证 FEEDBACK 短传输及 BUSY 降窗重试。
- HTTP 边界：控制 JSON 严格投影、请求长度与编码限制、提前拒绝非法帧前缀、非阻塞 BUSY 响应、源关闭和字节许可释放。

固定闭环已补齐 NONE/ZSTD、双 JVM 启动、持久输出重读和存储进程退出证据。原生调用中途不保证可立即中断，机器断电持久性不属于进程退出测试的结论。固定策略恢复链路已覆盖；有界观测和反馈策略已实现；受控性能实验已完成，预定研究收益未证实，见[实验报告](experiments/feedback-v1/README.md)。

## 生命周期与会话修复

R01：到期 OPEN/TRANSFERRING 持久收尾为 FAILED/EXPIRED，排空超时冻结；源缺少接受记录时先识别权威终态。新增假时钟与屏障回归覆盖新任务接纳、启动恢复、在途写入及 VERIFYING 的独立期限。

R02：运行时跨请求保留活动会话，历史终态快照不挤占活动索引。128/256/512 块的真实 HTTP 操作计数回归均只分配一次索引、普通请求回放 0 条记录、恢复 force 共 2 次；关闭并重开后各回放 N 条记录且再执行 2 次 force。另覆盖完成/取消/到期/冻结历史任务与新活动任务共存，原进程退出及恢复屏障回归保留。

R03：异步任务显式持有 Source，覆盖排队、接纳回调、读取和在途发送的取消；关闭一次，拒绝提交不接管输入，在途消费者退出前保留租约。

R04：先确定 Limits 与预算槽位，再收紧 FEEDBACK 区间和初始值并交叉校验；FIXED 无法满足则拒绝。回归覆盖空交集、帧/预算约束、恶意扩大或错误夹取，以及 NONE/ZSTD 真实 TLS 协商传输。

R05：状态文件版本与回执数量分别维护和恢复，源对账不再跨域比较版本。回归覆盖状态版本大于回执版本、分页期间追加、已确认条目缺失，以及重开和历史终态快照。

F01：取消通知不在任务锁内执行用户回调，避免同步取消回调关闭发送器时阻塞工作线程退出。带中断和不带中断的取消均通过屏障回归，Source 只关闭一次且预算归零。

R06：以完成顺序回收并补充有界槽位，不确定发送先排空、对账、重试。FIXED/FEEDBACK 屏障回归证明第 0 块阻塞时第 2 块仍可入场，最终输出和 Root 保持一致；满预算、取消及恢复回归保留。

R07：接收帧保留已验证视图直接进入 HPKE，移除整帧复制重编码往返；公共视图入口重新检查结构及配额。独立[帧分配诊断](experiments/frame-allocation-v1/README.md)显示目标转换段分配减少约 66.6%，预算和有效窗口保持不变。
