# 文件持久化

`FileSink` 是面向可信本地文件系统的参考适配器。根目录由进程锁独占，使用可信本地文件系统，并专用于当前 Sink。索引预算在构造时指定，每个允许的块索引占用 52 字节；超过预算的 Open 被拒绝。

每个 transferId 使用独立 UUID 目录，保存不可变 `open.cbor`、版本化 `state.cbor`、`payload.bin` 和 `receipts.log`。小控制记录通过同目录临时文件、force 和原子替换发布；启动时验证文件系统的原子替换能力。`.lcp-system` 用于文件系统能力检查。

FileSink 与源控制记录发布时，若原子替换返回 `AccessDeniedException`，对同一已 force 临时文件最多尝试 5 次，失败间隔 25 ms（累计等待最多 100 ms，不含文件系统调用耗时）。这可容忍短暂共享冲突；其他 I/O 错误立即返回，不降级为非原子写入。持续拒绝仍报错，等待被中断时保留中断状态并停止重试，目标会话继续遵守冻结语义。

块提交依次完成定位写、payload force、receipt 追加和日志 force，随后才发布内存索引及返回 receipt。相同描述符重放不追加日志；不同描述符或重叠范围不会覆盖已提交块。日志记录固定 68 字节，使用 CRC32C 检测记录损坏，载荷摘要使用 SHA-256。

恢复按记录流式填充有限索引，随后在既有顺序数组上按偏移原地堆排序，并检查相邻范围是否重叠。已按偏移有序的日志跳过排序；逆序重建的排序工作量为 O(n log n)，额外排序空间为 O(1)，每槽 52 字节预算不变。正常在线提交仍使用有序插入。恢复同时检查日志结构与持久化屏障：向查询和幂等提交发布索引之前，再次 force 载荷和日志。任一屏障失败会丢弃暂存索引、持久记录 RECOVERY_REQUIRED，并拒绝 receipt 查询；重新打开后继续保留冻结状态。只有末尾不足一条记录的片段可截断；完整记录 CRC 错误、范围错误、缺失载荷或完成态长度不符会进入 RECOVERY_REQUIRED。结果待核实的写入同样进入冻结状态。关闭等待实际 I/O 退出后释放资源并保留输出；超时不会释放根目录锁。

快速测试覆盖短写、持久重开、幂等、范围和配额、残片与 CRC 损坏、各写入边界异常、状态持久化及另一 JVM 的锁竞争。另有真实子进程在载荷写后、载荷 force 后、receipt 写后、receipt force 后、索引发布后、ACK 返回后、VERIFYING 持久化后和完成记录持久化后退出的测试；重开后保留已 ACK 块，并验证无 receipt 块可安全重交。根目录逃逸覆盖符号链接或 Windows junction。当前故障注入覆盖进程退出；机器断电与文件系统、硬件的联合验证列入[后续计划](roadmap.md)。完整传输重读校验由传输引擎负责。

源端 `SourceControl` 使用单独的进程锁和原子替换保存不超过 64 KiB 的版本化记录，内容仅包括端点、Open 意图、可空的接受事实及完成状态。记录在首次请求前写入，接受事实在读取输入前更新；载荷与块日志由传输数据路径管理。未知格式、路径逃逸或同路径的第二个源进程会被拒绝。

`TransferSink.expire(Instant)` 用于启动和新任务接纳前的到期清理，`SinkSession.expire(Instant)` 用于已认证请求入场。适配器必须停止新写入、排空已接纳 I/O 后持久终结；保留任务输出，并遵循已接纳 VERIFYING 的独立期限。

HTTP 运行时持有唯一活动 `SinkSession`；普通 Chunk、状态及 receipt 请求不关闭它，也不重新分配索引或回放日志。安全终结、切换或运行时关闭才释放会话；真正重开仍执行完整回放和 payload/log 的 force 屏障。

`TransferSink.terminalState(UUID)` 提供不建立第二份索引的历史终态快照。COMPLETED 使用持久结果中的最终计数并检查载荷长度；取消/失败状态通过固定大小记录缓冲读取日志计数。RECOVERY_REQUIRED 的日志重建发生异常时保留冻结状态，计数字段为零，写入事实以冻结记录与后续核查为准。快照提供终态查询；恢复 receipt 由完整会话提供，内容验证由 Finish 重读完成。历史终态状态查询及同请求 Open 重放不会挤掉活动会话；需要完整会话的历史 receipt、Chunk、Finish、Cancel 请求在另一个任务活动期间返回 BUSY，待活动任务安全终结后可重试。不会缓存所有历史任务或同时分配多份大索引。

`Status.revision` 仅随状态文件的持久变更递增；`ReceiptPage.revision` 是读取该页时唯一已提交回执的数量，从日志恢复。两者按各自语义独立使用。分页过程中新增提交可使回执版本增加，状态查询仍从同一索引视图读取已提交块数和字节数。
