# 文件持久化

`FileSink` 是面向可信本地文件系统的参考适配器。根目录由进程锁独占；不支持网络文件系统或其他进程修改输出。目录必须专用于该 Sink。索引预算在构造时指定，每个允许的块索引占用 52 字节；超过预算的 Open 被拒绝。

每个 transferId 使用独立 UUID 目录，保存不可变 `open.cbor`、版本化 `state.cbor`、`payload.bin` 和 `receipts.log`。小控制记录通过同目录临时文件、force 和原子替换发布；文件系统不支持原子替换时拒绝启动。`.lcp-system` 用于文件系统能力检查。

块提交依次完成定位写、payload force、receipt 追加和日志 force，随后才发布内存索引及返回 receipt。相同描述符重放不追加日志；不同描述符或重叠范围不会覆盖已提交块。日志记录固定 68 字节，使用 CRC32C 检测记录损坏，载荷摘要使用 SHA-256。

恢复按记录流式重建有限索引。只有末尾不足一条记录的片段可截断；完整记录 CRC 错误、范围错误、缺失载荷或完成态长度不符会进入 RECOVERY_REQUIRED。不确定写入同样冻结，不能自动继续。关闭会释放资源并保留输出。

快速测试覆盖短写、持久重开、幂等、范围和配额、残片与 CRC 损坏、各写入边界异常、状态持久化及另一 JVM 的锁竞争。异常注入不替代进程退出恢复验收；断电持久性还取决于文件系统和硬件。完整传输重读校验由传输引擎负责。
